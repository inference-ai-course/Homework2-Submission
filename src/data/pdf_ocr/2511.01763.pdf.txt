However, existing decompilation tech- niques often fail to produce source code that can be successfully recompiled and re-executed, particularly for optimized binaries. Recent advances in large language models (LLMs) have enabled neural approaches to decompilation, but the generated code is typically only semantically plausible rather than truly executable, limiting their practical reliability. These shortcomings arise from compiler optimizations and the loss of semantic cues in compiled code, which LLMs struggle to recover without contextual guidance. To address this challenge, we propose ICL4Decomp, a hybrid de- compilation framework that leverages in-context learning (ICL) to guide LLMs toward generating re-executable source code. We evaluate ICL4Decomp across multiple datasets, optimization lev- els, and compilers, demonstrating around 40% improvement in re-executability over state-of-the-art decompilation methods while maintaining robustness. Keywords Binary decompilation, Reverse engineering, In-context learning, Large Language Models, Compiler optimization 1 Introduction Binary decompilation aims to transform low-level binaries back into high-level source code and is a core problem in the areas of program analysis and software engineering [11]. It is critical for security auditing, vulnerability assessment, and malware reverse engineering [12, 57], especially when the original source code is unavailable. However, compilation is a lossy process [55]; it discards variable types [9], type annotations [58], control-flow constructs, and other semantic information that are crucial for comprehension and maintenance of the software. This loss of semantics leads to challenges when manually or automatically decompiling binaries, creating variable names like v1 and function names containing addresses like @xdeadbeef. Traditional decompilers (e.g., Hex-Rays [3], Ghidra [4]) rely on heuristic rules and control-flow analysis to identify source struc- tures like branches and loops. Setting aside the loss of symbols and other semantics, these decompilation tools can often generate rea- sonably accurate source code when the input binary is unoptimized. However, when optimizations have been applied to the input binary, Yuxin Hu Vanderbilt University Nashville, Tennessee, USA Kevin Leach Vanderbilt University Nashville, Tennessee, USA kevin.leach@vanderbilt.edu decompilers frequently generate source code that cannot be com- piled, that misunderstands the original developer’s intent, or that fundamentally changes the semantics of the decompiled program. For example, optimizations like loop unrolling or register reuse may destroy structural characteristics, leading to poor decompilation output. These tools are fundamentally limited in their attempt to simultaneously solve syntax recovery and semantic reasoning with fixed rules. Recently, neural network and LLM-based approaches (e.g., Dire [33], DeGPT [25], LLM4Decompile [49]) learn syntactic patterns through pre-training and generate readable code. How- ever, these techniques rely on statistical correlations (i.e., between ground truth human-written source and the generated decompiled source), and typically do not consider preserving semantics of the original program, instead focusing on optimizing for metrics like semantic matching BLEU [42] or ROUGE [37]. Moreover, these tools do not explicitly consider optimization semantics, leading to deviations in types, boundary conditions, and control correctness. Thus, there is a need to address current shortcomings in decompi- lation techniques, especially with respect to optimized binaries and the ability to re-compile and re-execute decompiled source. Given the limitations of existing work, decompilation faces two critical ongoing challenges: Challenge 1: Recovering Lost Se- mantics. Because binaries are often stripped of symbols (espe- cially in malware analysis or reverse engineering contexts), rich semantic information like control flow, variable names, and func- tion names are lost. Existing decompilation techniques rely on a combination of (a) machine learning (including LLMs), which is prone to overfitting, data quality, and statistical imbalance, and (b) formal methods, which do not scale well and create many false positives or overly-constrained typing judgments. In this paper, we consider augmenting LLM capabilities with well-grounded under- standing of decompilation and optimization rules to improve the quality of decompiled source. Challenge 2: Recompilability and Re-executability are second-class. Even when decompilation is successful and accurately reflects the original program semantics, existing tools almost never produce decompiled source that can be re-compiled to a binary, let alone execute successfully. Although de- compilation is often considered a one-way process at the moment, there are many applications where a user may want to re-compile the decompiled source to binary, including hot-patching [1, 31] and hardening medical device firmware [2, 5]. In this paper, we augment LLM-based decompilation tools in two key ways to im- prove the likelihood that decompiled source can be (a) re-compiled into a native binary, and (b) correctly execute and match outputs with the original program using a held-out test suite. By address- ing these challenges, our approach advances the state-of-the-art method in providing comprehensible decompiled source obtained from compiled software. To address the above challenges, we consider a mechanism for integrating descriptions of rules of transformations applied during compilation to facilitate working backwards — that is, leveraging the insight that compilers strictly adhere to semantics-preserving transformations, we integrate knowledge of these rules into LLM- based decompilation techniques using In-Context Learning (ICL) [15, 54]. ICL is a learning paradigm that enables LLMs to perform new tasks by conditioning on a few examples or instructions provided within the same input. Formally, the context refers to the augmented input supplied to the model during inference, which implicitly guides its predictions without additional parameter updates. In this domain, ICL enables conditioning decompilation on concrete demonstrations that exhibit desired semantic-syntactic correspon- dence. This technique achieves generation of the decompiled source that is more likely to re-execute and maintaining logical and struc- tural integrity with respect to the original input binary. Building upon the ICL paradigm, we propose ICL4Decomp, an in-context learning framework for decompilation. Our approach leverages two complementary knowledge sources to guide the decompilation process. First, context examples consisting of (bi- nary, source) pairs provide structural and semantic knowledge that demonstrate correct decompilation patterns. Second, optimization- aware rules encode constraints consistent with semantics-preserving compiler transformations during optimization, helping the model recognize and reverse common optimization patterns. The decom- pilation process operates end-to-end: given a target binary func- tion, we construct an informative context by selecting relevant examples or applicable rules, then condition the language model on this context to generate the corresponding source code. Our design combines the flexibility of ICL (which adapts to arbitrary binary input samples without retraining) with the interpretability of well-defined compilation transformation and optimization rules, ultimately providing a grounded decompilation framework that increases comprehensibility, re-compilability, and re-executability of decompiled binaries. We present an evaluation of our approach across multiple datasets under various optimization levels (00 to 03) and compilers (GCC and Clang), evaluating decompilation quality through re-executability rate, which (heuristically) measures whether the generated source code compiles and produces semantically-equivalent behavior to the original binary using a held-out test suite. Our results demon- strate substantial improvements over state-of-the-art baselines, achieving an average increase of approximately 40% in re-executability rate. The gains are particularly pronounced at higher optimization levels, where compiler transformations introduce greater seman- tic ambiguity and structural complexity. Notably, ICL4Decomp maintains robust performance across all optimization levels, indi- cating that our framework effectively handles diverse compilation transformations. These findings validate that integrating context examples with optimization-aware knowledge enables more re- liable semantic reasoning and syntax recovery, bridging the gap between binary analysis and executable code generation in practi- cal decompilation scenarios. Together, these results highlight the potential of in-context learning as a general mechanism for reverse- engineering tasks, demonstrating that decompilation can benefit from contextual, example-driven adaptation. To support retrieval-based in-context learning, we build a retrieval infrastructure that encodes assembly functions into a dense embedding space and enables efficient, se- mantically aware exemplar search. In this subsection, we aim to present how exemplars are represented and retrieved efficiently. Corpus Construction and Embedding. To enable effective in-context learning of binary decompilation, we first need a corpus that pro- vides diverse and representative function pairs for retrieval-based prompting. We construct the corpus from two widely adopted sources: MosTLy BASIC PROGRAMMING PROBLEMS (MBPP) bench- mark [7], commonly used for evaluating code generation models, and ExeBench [6], frequently used in training large code mod- els. This design ensures both popularity and diversity, combining algorithmic-level codes from MBPP with system-level codes from ExeBench. Together, these sources yield approximately 10° unique (Aj, S;) pairs spanning a broad range of programming patterns and compiler behaviors. To ensure consistency across compilers and architectures, all assembly functions are normalized by removing comments and reg- ister prefixes (%), inserting uniform whitespace around punctuation, converting hexadecimal constants to decimal form, and replacing instruction addresses with symbolic placeholders (e.g., LINST-1]), following the preprocessing used by a foundation model [27]. Cor- responding C source codes are stripped of header inclusions and reformatted into canonical style. Each pair is further annotated with a functional category (algorithm, string, io, system, or math) in- ferred from library headers and API calls, along with auxiliary attributes such as lines of code and cyclomatic complexity. Exact duplicates are removed via content hashing. Each assembly function A; is encoded into a vector h(Aj) € R?¢ using the encoder component of the pretrained generative founda- tion model Nova [27], which is specifically designed for assembly code understanding. Nova is well-suited to our objective due to two key learning strategies: (i) Functionality Contrastive Learning, which encourages embeddings of functionally equivalent assem- bly snippets— e.g., variants compiled from the same source—to be encoded closer in latent space; and (ii) Optimization Contrastive Learning, which enforces an orderly embedding geometry across compiler optimization levels (00-03), such that heavily optimized binaries are positioned progressively farther from their unoptimized counterparts. Together, these mechanisms enable this encoder to prioritize functional semantics over surface syntax, which ensures that exemplars retrieved for decompilation reflect true functional similarity, thereby improving the executability of the decompiled source code. We use the mean of all [INST] token embeddings as the final representation h(A;) for each assembly function. All embeddings are precomputed and indexed using FAISS, enabling millisecond-scale retrieval during in-context exemplar search. Similarity-Based Retrieval with Category-Aware Re-ranking. Given this embedded corpus, we retrieve exemplars for each target func- tion through similarity-based search with category-aware adjust- ments. For a target assembly function A; with embedding h(A;), we compute its similarity to each candidate A; in the corpus using Cross-domain Similarity Local Scaling (CSLS) between h(A;), and h(A;), which mitigates the hubness problem, where certain points become nearest neighbors to disproportionately many queries, com- mon in high-dimensional embedding spaces. To promote semantic relevance beyond purely structural similarity, we apply a category- aware re-ranking that multiplies the similarity score by a penalty factor a when the functional categories of A; and A; do not match, yielding an adjusted score s’(A;, Aj). This design balances exploit- ing known functional similarity with exploring structurally related but categorically distinct examples. The next section extends the paradigm by incorporating another contextual form. 3.2 ICLD-O: Optimization Rule-based ICL While retrieved exemplars effectively expose the model to compiler- style mappings, they assume that instruction-source alignments remain locally consistent. However, specific compiler optimization flags often introduce systematic yet non-trivial transformations, e.g., eliminating stack frames, unrolling loops, or fusing arithmetic operations, that break these correspondences. These transforma- tions often alter the variable—-register mapping so aggressively that the LLM fails to infer correct data flow, leading to syntactically valid but semantically incorrect decompilation outputs. To address this limitation, we introduce ICL4D-O, a rule-based variant of in-context decompilation that explicitly contextualizes the model with compiler optimization semantics. Rather than rely- ing solely on retrieval, ICL4D-O augments the prompt with natural- language descriptions of the optimization rule(s) applied to the target binary, helping the LLM reconstruct high-level code consis- tent with the compiler’s intent. 3.2.1. Optimization Flag Selection. Modern compilers expose hun- dreds of fine-grained optimization flags (e.g., -ftree-dominator-opts, -fmerge-constants, -fomit-frame-pointer, -funswitch-loops, etc.), many of which are interdependent and architecture-specific. It is therefore impractical—and conceptually noisy—to design prompts for all available flags. To ensure that our rule-based study focuses on the most impactful transformations, we empirically identified which optimization flags are actually active in our corpus. Specifically, we performed a simple but systematic binary search analysis over compiler options. Given a random subset of functions from the corpus, we maintained a candidate list of optimization flags F extracted from GCC/Clang documentation. For each flag fj © F, we compiled the same source twice—once with f; enabled and once with it disabled—while keeping all other conditions fixed. We then compared the resulting assembly outputs token-wise. A flag is considered active if the two assembly versions differ in instruction sequence, register allocation, or control-flow structure. By iteratively bisecting the flag list—grouping related options and testing subsets—we efficiently determined which flags have a measurable effect on real compilation outputs within our dataset. The empirical frequency of activation across sampled corpus func- tions yielded a ranked list of influential optimizations. From this analysis, we selected the top five most frequently active flags: -fomit-frame-pointer, -ftree-ter, fipa-pure-count, -fcrossjumping, and -ftree-coalesce-vars. These options con- sistently altered the emitted assembly structure and therefore rep- resent diverse and meaningful compiler transformations for LLM- based decompilation analysis. This data-driven selection ensures that the rule-based prompts in ICL4D-O target real, observable compiler behaviors rather than theoretical or rarely-triggered optimizations, providing a grounded and practically relevant evaluation. 3.2.2 Rule-based Prompt Design. [CL4Decomp is designed to be model-agnostic as ICL can be readily adapted to many existing LLM architecture, including open-source models such as DeepSeek, Qwen, and CodeL- lama, as well as commercial models like GPT-4 and Claude. For sce- narios involving privacy or code security concerns, ICL4Decomp can be deployed locally with open-source models to enable offline decompilation. The framework is fully decoupled at the API layer, making it facilitating integration into existing analysis platforms like IDA or Ghidra through plugin interfaces. Because ICL4Decomp operates entirely at inference time and does not require any model retraining, it is particularly suitable for environments with limited resources or cases where the original source code is unavailable. In practice, our framework can be applied to several binary analysis tasks, including security auditing, patch analysis, and reverse engi- neering, while maintaining consistent performance across different compiler optimization levels. Cost Analysis. The primary cost of ICL4Decomp arises from API- based LLM invocations, which include: (a) the assembly code and retrieved exemplars used to construct the in-context prompt, and (b) the generated source code output. Since individual functions are relatively short (typically under 300 tokens), the per-sample inference cost remains significantly lower than in general-purpose code generation tasks. For example, when using DeepSeek V3.2 on the HumanEval-Decompile dataset, the total cost for decompiling the entire benchmark is approximately $3. In terms of runtime, ICL4Decomp achieves high throughput through a multi-worker parallel execution mechanism. By distribut- ing decompilation requests across multiple workers on a single multi-core workstation, decompiling 1,000 functions requires only about 15 minutes. This near-linear scalability with respect to the number of workers makes the framework suitable for large-scale binary analysis in real-world settings. Overall, ICL4Decomp demon- strates strong portability across models and deployment environ- ments, and its inference cost scales linearly with workload size, supporting practical use in security and engineering applications. 6.2 Threats to Validity Internal Validity. LLM inference inherently involves random- ness (e.g., due to sampling temperature), which may affect re- executability. To mitigate this, we fix the random seed to 42 and set the sampling temperature to 0.1, minimizing stochastic variation across runs. Although our experiments cover optimization levels from O00 to O3, the dataset is limited to single-function compilation; thus, certain global optimization patterns (e.g., link-time optimiza- tion) are not included, and the results may be conservative for more aggressive optimization scenarios. Our current implementation of ICL4D-O uses a predefined pool of optimization rules to construct contextual prompts. We intention- ally avoid dynamically inferring the active optimization set from each assembly function, since identifying which compiler flags were applied is inherently ambiguous and nontrivial—many flags interact or produce overlapping instruction-level effects. However, enabling adaptive rule selection based on automatically detected optimization patterns could further improve contextual relevance, and represents an interesting avenue for future exploration. External Validity. Our evaluation is conducted at the function level, emphasizing syntactic and semantic re-executability of de- compiled binaries obtained from single functions. We select two representative benchmarks (ExeBench and HumanEval-Decompile) used in other works [16, 17, 22, 49] with distinct characteristics and report stratified results by structural complexity, including lines of code, cyclomatic complexity, and basic block count (cf. sec- tion 4). While system-level and multi-function programs are not the primary focus of this study, our framework does not rely on dataset-specific features; extending it to broader codebases primar- ily requires adjusting the contextual composition strategy. Nonethe- less, our evaluation follows best practices in rigorously evaluating LLM-based decompilation techniques. 7 Related Work 7.1 Neural Decompilation and Binary-to-Source Translation Traditional rule-based decompilers (e.g., Hex-Rays [3], Ghidra [4]) rely on pattern heuristics that often fail under compiler optimiza- tions and aggressive inlining. Neural approaches instead learn corre- spondences between binary instructions and high-level abstractions to generate source code that is both functionally equivalent and compilable to the original binary behavior. Most neural methods follow the Neural Machine Translation (NMT) paradigm [48], adapting a sequence-to-sequence model to map low-level binaries to high-level source code. Early work em- ploys Recurrent Neural Networks (RNNs) [29] to translate binary code directly into C source code. TraFix [30] combines NMT with program analysis for better usability. DIRE [33] tokenizes assem- bly-source pairs but suffers from limited context and sparse vocab- ularies. Coda [20] targets semantic correctness through an end-to- end neural framework but degrades on complex ISAs. More recent work, including LLM4Decompile [49, 50] and DecompileBench [21], leverages pretrained LLMs achieving improved fluency but reveals reliability issues due to uncontrolled generalization. Despite notable progress, current neural decompilers still strug- gle with cross-compiler generalization and semantic consistency [9, 32]. Many models generate syntactically valid code that fails to recompile or execute equivalently. Reconstruction of high-level structures, such as loops, branches, and call hierarchies, remains limited in purely neural approaches, reflecting persistent difficul- ties in maintaining readability and structural coherence [13, 44, 52]. These limitations motivate the integration of retrieval-based and compiler-aware contextualization strategies to enhance robustness and interpretability. 7.2 Large Language Models for Code Intelligence LLMs have redefined the landscape of code understanding and generation [10, 14, 26, 51]. Early transformer-based encoders such as CodeBERT [18], GraphCodeBERT [23], UniXCoder [24], and CodeT5 [53] capture bidirectional code semantics and effectively align program syntax with natural language descriptions. Gen- erative models such as Codex [10], AlphaCode [36], and CodeL- lama [43] extend these capabilities through large-scale instruction tuning, enabling complex synthesis, refactoring, and reasoning tasks. Execution-aware frameworks including CodeRL [34], Self- Refine [40], and Reflexion [46] further incorporate runtime feedback to improve the functional correctness of generated code. General-purpose LLMs such as GPT-4 can assist in reasoning over disassembly and decompiled code [28]. Concurrent research on transformer-based binary embeddings enhances control-flow rep- resentations and structural understanding [59]. Frameworks such as ReSym [56] demonstrated the feasibility of combining symbolic reasoning with pretrained code models. In parallel, source-code foundation models have been explored as transferable knowledge bases for binary analysis, showing that code-pretrained LLMs cap- ture low-level semantics applicable to disassembled programs [47]. Empirical evaluations on binary-analysis tasks show that LLM performance varies substantially across compilers, optimization levels, and task types [28, 45]. Studies of code-oriented LLMs fur- ther document frequent hallucinations that can lead to functional errors [38]. For stripped binaries, the lack of explicit compiler se- mantics and symbol information degrades type and variable recov- ery unless augmented with program-analysis signals [56]. Hybrid pipelines that pair LLMs with binary encoders or code-foundation models provide external grounding and improve recovery qual- ity [47]. These findings motivate retrieval-augmented and structure- aware prompting to stabilize low-level reasoning and improve re- producibility in binary-to-source workflows [45, 47]. 7.3 In-Context Learning for Program Synthesis In-context learning (ICL) enables LLMs to adapt to new program- ming tasks without parameter updates by conditioning generation on exemplar demonstrations [8], showing strong generalization in few-shot code synthesis and repair [10]. In program synthesis, ICL facilitates rapid adaptation to unseen codebases, problem styles, or programming languages using a small number of exemplars [41]. Models such as GPT-3, Codex, and StarCoder demonstrate robust few-shot capabilities for code generation and completion when supplied with representative in-context examples [10, 35]. Wang et al. Frameworks such as Self-Edit and InCoder use few-shot exem- plars to preserve syntactic correctness and logical consistency dur- ing code modification [19, 40]. Recent retrieval-augmented methods employ semantically similar exemplars drawn from large code cor- pora to improve synthesis reliability and domain transfer [39]. In binary-to-source translation, ICL provides a natural way to incor- porate compiler- and optimization-specific context by retrieving representative (assembly, source) exemplars [28, 47]. Empirical analyses show that exemplar similarity—measured via code embeddings, opcode overlap, or control-flow distance—strongly affects output fidelity [39, 41]. Integrating retrieval with in-context prompting thus provides a robust paradigm for cross-optimization decompilation, combining explicit structural grounding with the generalization power of pretrained LLMs [45]. 8 Conclusion This paper presents ICL4Decomp, a unified in-context learning framework for executable decompilation that jointly addresses syn- tactic recovery and semantic reasoning. It introduces two comple- mentary mechanisms: ICL4D-R, which retrieves assembly-source exemplars to provide structural priors, and ICL4D-O, which in- jects optimization semantics through rule-based natural-language prompts. Together, they enable bidirectional alignment between syntax and semantics during inference. Across ExeBench and HumanEval-Decompile, ICL4Decomp im- proves the re-executability rate by approximately 40% on average, with particularly strong gains under higher optimization levels (01-03). It effectively reduces syntax and declaration errors, while maintaining robustness to function complexity and context length. These results demonstrate that in-context learning offers a practical and reproducible way to achieve executable consistency without model retraining. Future work will explore hybrid context composition between retrieval and rule-based prompting, automatic inference of compiler optimization patterns, and broader generalization across compil- ers and architectures.
